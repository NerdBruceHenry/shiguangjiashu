# 时光家书

把现在的声音、字、照片和画封进信里，等孩子长大那天再拆。纯网页（PWA），没有服务器、没有 AI、没有第三方库，可离线使用。

## 怎么用

1. 打开网页，建信箱：孩子的称呼、生日、一个口令。
2. 抄下**恢复码**（忘记口令时唯一的办法），和户口本放在一起。
3. 写信：文字、录音、照片、画画，也可以带入《出口成章》的作文。选拆信的日子，封好。
4. 每月写一封，首页多一颗星。到了日子，用口令拆开。
5. 「保管与备份」里存一份**时光匣**：一个能自己打开的网页文件，离线、没有本工具也能用口令读信。

「每年五问」每年答同样的五个问题，拆信后可以按年龄并排看。

## 安全设计

- **写信不需要口令**：封信用信箱公钥（ECDH P-256 + HKDF + AES-256-GCM），拆信用私钥。私钥分别用口令和恢复码（PBKDF2-SHA256，60 万次）加密保存。
- 信封上的寄信人、日期、拆信日、封面字**不加密**，但参与校验，改一个字信就打不开。
- 正文、录音、照片、画全部加密；照片会重新编码，去掉拍摄地点。**草稿在封信之前是明文**，存在本机。
- 没有统计，不联网；只有主动开启 GitHub 备份时才访问 `api.github.com`，上传的是密文，只接受私有仓库。

### 需要知道的局限

- **日期锁是约定，口令才是真正的锁。** 知道口令又会改代码或改系统时间的人，可以提前拆信。所以口令由大人保管。
- 口令和恢复码都丢了，信永远打不开。
- 换口令后，旧的时光匣文件仍用旧口令。
- 浏览器数据可能被清除，**没有备份就等于没有保存**。至少存两个地方，每年体检一次。

## GitHub 自动备份（可选）

1. 新建一个 **Private** 仓库（不要用本代码仓库）。
2. Settings → Developer settings → Fine-grained tokens，只选那一个仓库，权限 Contents: Read and write。
3. 填进「保管与备份」。令牌只存在本机浏览器，会过期，过期后重新填。

## 开发

`npm test` 运行测试；改文件后运行 `node tools/gen-sw.mjs` 更新离线缓存。推送到 `main` 会自动测试并部署到 GitHub Pages（Settings → Pages → Source 选 GitHub Actions）。

`js/crypto.js` 的格式一旦有人用就不能改，只能加新版本，否则旧信打不开。
